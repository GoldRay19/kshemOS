# Contributing to KshemOS

Thank you for your interest in contributing to **KshemOS**! We welcome developers, designers, researchers, writers, and community members who want to help improve the project.

## How to Contribute

### 1. Fork the Repository

Create your own fork of the KshemOS repository and clone it locally.

### 2. Create a Branch

Create a dedicated branch for your changes:

```bash
git checkout -b feature/your-feature-name
```

Use a descriptive branch name such as:

* `feature/emergency-alerts`
* `fix/map-display`
* `docs/update-readme`

### 3. Make Your Changes

Implement your feature, fix, documentation update, or improvement.

Please keep changes focused and avoid unrelated modifications in the same pull request.

### 4. Test Your Changes

Before submitting a pull request:

* Test the affected functionality.
* Check for console errors.
* Make sure existing functionality still works.
* Verify responsive behavior where applicable.
* Keep the code clean and readable.

### 5. Commit Your Changes

Use clear and meaningful commit messages:

```bash
git add .
git commit -m "Add emergency alert interface"
```

### 6. Push Your Branch

```bash
git push origin feature/your-feature-name
```

### 7. Open a Pull Request

Create a pull request against the main KshemOS repository.

In your pull request, describe:

* What you changed
* Why you made the change
* How you tested it
* Any relevant screenshots or references

## Code Style

Please follow the existing coding conventions used throughout the project.

* Write readable and maintainable code.
* Use meaningful variable and function names.
* Avoid unnecessary complexity.
* Keep components and modules focused.
* Add comments where they improve understanding.
* Do not commit secrets, API keys, passwords, or private information.

## Issues and Bug Reports

When reporting a bug, please include:

* A clear description of the issue
* Steps to reproduce it
* Expected behavior
* Actual behavior
* Browser/device information when relevant
* Screenshots or logs when useful

## Feature Requests

Feature requests are welcome. Please explain:

* The problem the feature would solve
* How the proposed feature would work
* Why it would benefit KshemOS users

## Security

Please do **not** publicly disclose security vulnerabilities or sensitive security information in GitHub issues.

Report security concerns privately through the project's designated security contact or repository security process.

## Community Contributions

Contributions are not limited to code. You can also help with:

* Documentation
* UI/UX improvements
* Accessibility
* Testing
* Bug reports
* Feature ideas
* Research
* Community support

## Pull Request Guidelines

Pull requests should:

* Have a clear title.
* Explain the purpose of the change.
* Contain focused changes.
* Pass relevant tests.
* Follow the project's coding conventions.
* Avoid unnecessary dependencies.

Maintainers may request changes before a pull request is merged.
